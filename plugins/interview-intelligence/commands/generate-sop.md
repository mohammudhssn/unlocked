# Skill: Generate SOP

## When to Use
After Session 3 (Knowledge Mapping). Run this to produce a first-draft SOP from the knowledge pillar taxonomy. Review and complete in Session 4 or async with the expert.

## Context
The SOP codifies the expert's tacit knowledge into a transferable, step-by-step process document. It's both a product (sell to domain peers) and a foundation for any venture built from the engagement.

Read the `templates/sop-pack.md` template before producing output.
Read `outputs/knowledge-pillars.md` and all session syntheses.

## Instructions
1. Read all session notes and the knowledge pillar taxonomy
2. Identify the process with the highest tacit knowledge density — look for:
   - The pillar the SME spent the most time on
   - The step or decision that "takes years to really get"
   - The workaround they use that nobody officially endorses
3. Structure the process into the SOP format from `templates/sop-pack.md`:
   - Step-by-step instructions
   - "What good looks like" for each step
   - "What bad looks like" (failure modes)
   - "Expert Insight" sections populated from tacit knowledge signals in session notes
4. Use the SME's exact vocabulary throughout
5. Mark any sections that need more expert input with `[NEEDS REVIEW]`
6. Add a Quick Reference Card at the end (the one-page version)

## Output
`outputs/sop-draft.md`

The SOP draft should be complete enough to review with the expert in Session 4. Their feedback on what's missing or inaccurate is the most valuable part of the review.
